# 个人股票 AI 追踪 Agent — 需求文档

> 版本：v1.0 · 日期：2026-07-07 · 状态：待确认数据源方案后进入实现

## 1. 目标与范围

**目标**：根据配置的股票代码列表（A股 + 港股），每个交易日收盘后自动生成一份追踪报告。

**成功标准**：
- 工作日收盘后无人工干预自动产出报告
- 报告一屏内可看清每只股票的行情、技术、资金三类信息
- 命中异动阈值的个股被自动高亮置顶

**本期范围**：
- ✅ 行情走势追踪（不含持仓盈亏）
- ✅ 阈值提醒（涨跌幅、量比）
- ✅ 公告追踪（重要类型过滤，纯规则）
- ✅ 财报追踪（披露提醒 + 关键财务数据 + 业绩预告/快报）
- ✅ 风险消息（关键词命中高亮，纯规则）
- ✅ 本地文件输出（HTML + Markdown）→ GitHub Actions 提交回仓库
- 🔜 预留但默认关闭：AI 摘要层（读懂公告/新闻、风险分级）、微信/IM 推送

**明确不做（本期）**：
- 持仓成本 / 盈亏计算
- 买卖建议 / 投资决策
- 实时盘中监控（仅收盘后日频）

## 2. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 平台 | .NET 10 (LTS) | Console App |
| 运行形态 | GitHub Actions（cron 定时） | 工作日云端触发，无需本机开机 |
| 数据采集 | `HttpClient` + `System.Text.Json` | 封装东方财富/新浪公开行情接口 |
| 配置 | `appsettings.json` | .NET 原生配置绑定 |
| 指标计算 | 纯 C# | 无三方依赖 |
| 报告模板 | Scriban | 生成 Markdown + HTML |
| 投递 | 本地文件（默认） | 推送接口预留 |
| AI 摘要 | `ISummarizer`（默认 NoOp） | 预留可插拔，默认关闭 |

### 数据源说明（关键）
.NET 无 akshare/efinance 等价库。方案为用 `HttpClient` 直接调用以下公开接口，自行封装解析：

| 类别 | 主源 | 备用源 |
|---|---|---|
| 行情/技术/资金 | 东方财富 push2 接口 | 新浪 hq 接口 |
| A股公告 | 巨潮资讯(cninfo) 公告查询接口 | 东财公告接口 |
| 港股公告 | 港交所披露易(hkexnews) | 东财公告接口 |
| 财报/业绩预告/快报 | 东财财务数据接口 | — |
| 个股新闻 | 东财/新浪个股新闻流 | — |

## 5. 功能需求

### 5.1 数据采集（收盘后触发）
- 行情：现价/收盘价、涨跌额、涨跌幅、成交量、成交额、换手率、量比、振幅
- 技术面：MA5 / MA20 / MA60、近 5 日 / 20 日涨跌幅、是否创阶段新高/新低
- 资金面：北向资金（A股）、南向资金（港股）、主力净流入
- 数据源失败时自动切换备用源并记录日志

### 5.2 指标计算与阈值判定
- 计算上述技术指标
- 命中 `PctChangeThreshold`（|涨跌幅| ≥ 阈值）或 `VolumeRatioThreshold`（量比 ≥ 阈值）的个股标记为"异动"

### 5.3 公告追踪（纯规则）
- 抓取每只股票"今日新增公告"（含标题、公告类型、发布时间、原文链接）
- **重要类型过滤**：仅保留重要公告类型（业绩、分红、重组、增减持、股权质押、诉讼仲裁、监管处罚、问询函、停复牌等），过滤例行/事务性公告
- 命中风险关键词的公告在报告中高亮（见 5.6）

### 5.4 财报追踪（纯规则）
- **披露提醒**：今日已披露财报提示 +（若可得）未来披露日历
- **关键财务数据**：营收、净利润、同比/环比、毛利率等核心指标
- **业绩预告/快报**：抓取预告/快报类型与预告净利变动区间（往往是股价异动先行信号）

### 5.5 风险消息（纯规则/关键词）
- 抓取个股新闻流 + 公告标题，按**可配置关键词**命中高亮
- 默认关键词：减持、质押、冻结、诉讼、仲裁、处罚、违规、ST、退市、问询函、商誉、停牌、下调评级、大股东变动等
- 命中项在报告"风险提示区"集中展示（标题 + 类型 + 链接），不解读内容
- 🔜 预留：启用 AI 后由 summarizer 补充一句话摘要与利好/中性/利空分级

### 5.6 报告生成
- **组合概览**：涨跌家数、平均涨跌幅、领涨/领跌个股
- **风险提示区**：命中风险关键词的公告/新闻集中置顶
- **异动提醒区**：命中阈值个股置顶
- **个股卡片**：行情 + 技术 + 资金 + 当日公告 + 财报/业绩信息
- 输出 `reports/YYYY-MM-DD.html` 与 `.md`

### 5.7 投递
- 默认：写入 `reports/` 目录文件，由 GitHub Actions 提交回仓库（可选开 GitHub Pages 网页查看）
- 预留：`IReportDelivery` 接口，后续接企业微信 Webhook / Server酱

### 5.8 AI 摘要（预留，默认关闭）
- `ISummarizer` 接口，默认 `NoOpSummarizer`
- 后续可接 `claude-haiku-4-5`：当日异动原因摘要、公告/新闻一句话摘要与利好/中性/利空风险分级

## 6. 调度（GitHub Actions cron）
- 工作日触发；cron 为 UTC 且高峰期可能延迟数分钟，需留缓冲
- 时间换算：A股 15:30 CST = 07:30 UTC、港股 16:30 CST = 08:30 UTC
- 建议：统一设 09:00 UTC（17:00 CST）收盘后一次触发，留足缓冲
- 报告产物通过 `git commit` 回仓库持久化（runner 为临时环境，文件不落地）
- 采集层需重试 + 备用源 + 失败日志，应对海外 runner 访问中国行情接口的限流/失败风险

## 7. 非功能需求
- 配置与逻辑分离、无硬编码本地路径 → 便于后续迁移云端
- 网络请求含超时、重试、失败降级
- 日志记录采集与生成过程，便于调试

## 8. 已确认决策
1. ✅ 数据源：直接调用东方财富/新浪/巨潮/披露易 HTTP 接口
2. ✅ 调度：GitHub Actions cron，统一 09:00 UTC（北京 17:00）触发一次
3. ✅ 公告/风险：纯规则 + 关键词，重要类型过滤，AI 层预留默认关闭
4. ✅ 财报：披露提醒 + 关键财务数据 + 业绩预告/快报

## 9. 已知风险
- 海外 GitHub runner 访问中国行情/公告接口可能限流或失败 → 实现第一步先做最小连通性验证
- 公告/新闻源接口可能变更或有反爬 → 采集层需容错、限速、UA 伪装
