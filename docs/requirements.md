# 个人股票 AI 追踪 Agent — 需求文档

> 版本：v1.1 · 日期：2026-07-10 · 状态：实现中；v1.1 新增持仓展示与规则型买卖点

## 1. 目标与范围

**目标**：根据配置的股票代码列表（A股 + 港股），**每周五收盘后（周跟踪）**自动生成一份追踪报告。

**成功标准**：
- 每周五收盘后无人工干预自动产出周报
- 报告一屏内可看清每只股票的持仓、估值（当前市值 vs 买卖点）、年内涨幅与公告/财报/风险信息
- 命中"理想买点"（可以击球）的个股被自动红色高亮置顶

**本期范围**：
- ✅ 行情走势追踪（现价、当前市值等基础行情）
- ✅ **持仓展示（v1.1）**：持股份数、成本价、持股比例、当前市值、年内涨幅
- ✅ **规则型买卖点（v1.1）**：按配置的总市值阈值判定"理想买点/1年内卖点"，命中"可以击球"红色高亮（纯阈值，不含 AI 解读/建议理由）
- ✅ 公告追踪（重要类型过滤，纯规则）
- ✅ 财报追踪（披露提醒 + 关键财务数据 + 业绩预告/快报）
- ✅ 风险消息（关键词命中高亮，纯规则）
- ✅ 本地文件输出（HTML + Markdown）→ GitHub Actions 提交回仓库
- 🔜 预留但默认关闭：AI 摘要层（读懂公告/新闻、风险分级）、微信/IM 推送

**明确不做（本期）**：
- 盈亏的自动解读 / 卖出理由分析（买卖点仅为纯阈值机械提示，不含决策建议）
- ~~技术指标（MA5/20/60、近 5/20 日涨跌幅）、量比/换手率/涨跌幅展示、异动阈值提醒、主力净流入~~ **（v1.1 移除，见下）**
- 实时盘中监控（仅收盘后日频）

> **v1.1 范围变更说明**：
> 1. v1.0 原将"持仓成本/盈亏""买卖建议"列为不做。v1.1 经用户确认放开——引入持仓展示与**规则型**（纯总市值阈值）买卖点提示。仍不做的是 AI 型的决策建议与理由解读。
> 2. **移除技术/短期指标**：经用户确认，v1.1 **彻底移除**涨跌幅、量比、换手率、MA5/MA20/MA60、近 5/20 日涨跌幅、主力净流入等 K 线/技术/资金指标；**异动阈值提醒功能一并去掉**（含 `Alerts` 配置与报告异动提醒区）。报告转为聚焦"持仓 / 估值 / 买卖点"。K 线数据源保留（年内涨幅需年初收盘），但不再计算上述指标；资金流数据源停用。

## 2. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 平台 | .NET 10 (LTS) | Console App |
| 运行形态 | GitHub Actions（cron 定时） | 工作日云端触发，无需本机开机 |
| 数据采集 | `HttpClient` + `System.Text.Json` | 封装东方财富/新浪公开行情接口 |
| 配置 | `appsettings.json` | .NET 原生配置绑定 |
| 指标计算 | 纯 C# | 无三方依赖 |
| 报告模板 | Scriban | 移动优先单列卡片；生成 Markdown + 响应式 HTML + 公众号内联样式导出(预留) |
| 投递 | 本地文件（默认） | 推送接口预留 |
| AI 摘要 | `ISummarizer`（默认 NoOp） | 预留可插拔，默认关闭 |

### 数据源说明（关键）
.NET 无 akshare/efinance 等价库。方案为用 `HttpClient` 直接调用以下公开接口，自行封装解析：

| 类别 | 主源 | 备用源 |
|---|---|---|
| 行情（现价/总市值 `f116`） | 东方财富 push2 接口 | 新浪 hq 接口 |
| K 线（仅供年内涨幅取年初收盘） | 东方财富 K 线接口 | — |
| 汇率 HKD→CNY（港股金额折算） | 东方财富外汇接口 | 配置的静态汇率（回退） |
| A股公告 | 巨潮资讯(cninfo) 公告查询接口 | 东财公告接口 |
| 港股公告 | 港交所披露易(hkexnews) | 东财公告接口 |
| 财报/业绩预告/快报 | 东财财务数据接口 | — |
| 个股新闻 | 东财/新浪个股新闻流 | — |

> v1.1 已停用资金流（主力净流入）数据源；K 线源保留但仅用于取年初收盘价算年内涨幅，不再计算 MA / 近 N 日涨跌幅。

## 5. 功能需求

### 5.1 数据采集（收盘后触发）
- 行情：现价/收盘价、**总市值（东财 push2 `f116`）**（涨跌幅、成交量、换手率、量比等字段接口会一并返回，但 v1.1 不展示也不使用）
- K 线：仅取年初首个交易日收盘价，供年内涨幅计算（不再计算 MA / 近 N 日涨跌幅）
- 汇率：HKD→CNY（东财外汇接口），供港股金额折算；取数失败回退配置的静态汇率
- 数据源失败时自动切换备用源并记录日志

> **v1.1 移除**：技术面（MA5/20/60、近 5/20 日涨跌幅、阶段新高/新低）与资金面（北向/南向、主力净流入）采集与计算全部删除。

### 5.2 指标计算与阈值判定 —— **（v1.1 移除）**
> 原基于涨跌幅/量比的异动阈值提醒功能已删除（含 `Alerts` 配置与报告异动提醒区）。v1.1 报告不含任何技术指标与异动判定，改以持仓/估值/买卖点为核心（见 5.6）。

### 5.3 公告追踪（纯规则）
- 抓取每只股票**"本周新增公告"（近 7 天，按发布时间过滤）**（含标题、公告类型、发布时间、原文链接）
- **重要类型过滤**：仅保留重要公告类型（业绩、分红、重组、增减持、股权质押、诉讼仲裁、监管处罚、问询函、停复牌等），过滤例行/事务性公告
- 命中风险关键词的公告在报告中高亮（见 5.5）

### 5.4 财报追踪（纯规则）
- **披露提醒**：**本周（近 7 天）已披露**财报提示 +（若可得）未来披露日历
- **关键财务数据**：营收、净利润、同比/环比、毛利率等核心指标
- **业绩预告/快报**：抓取预告/快报类型与预告净利变动区间（往往是股价异动先行信号）

### 5.5 风险消息（纯规则/关键词）
- 抓取个股**近 7 天**新闻流 + 公告标题，按**可配置关键词**命中高亮
- 默认关键词：减持、质押、冻结、诉讼、仲裁、处罚、违规、ST、退市、问询函、商誉、停牌、下调评级、大股东变动等
- 命中项在报告"风险提示区"集中展示（标题 + 类型 + 链接），不解读内容
- 🔜 预留：启用 AI 后由 summarizer 补充一句话摘要与利好/中性/利空分级

### 5.6 持仓与买卖点追踪（v1.1，纯规则）

报告为每只股票新增以下展示列，全部走**公司总市值**口径，量纲一致：

| 字段 | 来源 | 计算/说明 |
|---|---|---|
| 持股份数 | 配置 `Shares` | 观察池股票可空，空则相关列显示"—" |
| 成本价 | 配置 `CostPrice` | 观察池可空 |
| 理想买点 | 配置 `IdealBuyMarketCapYi` | 目标总市值（**亿元人民币**，含港股） |
| 1年内卖点 | 配置 `SellMarketCapYi` | 目标总市值（**亿元人民币**，含港股） |
| 当前市值 | 取数 + 折算 | 公司总市值 = 现价 × 总股本，取自东财 push2 `f116`；**港股按 HKD→CNY 折算为人民币**（亿元人民币） |
| 持仓市值 | 计算 + 折算 | 现价 × 持股份数（份数为空则不计）；**折算为人民币** |
| 持股比例 | 计算 | 该股持仓市值 ÷ 全部持仓总市值（均折人民币后计；**分母仅统计有持仓的股票，观察池不计入**） |
| 年内涨幅 | 计算 | (现价 − 年初首个交易日收盘) ÷ 年初收盘 |
| 对成本盈亏（卡片） | 计算 | 核心持仓卡片一行：金额 =（现价 − 成本价）× 份数（折人民币）；收益率 =（现价 − 成本价）÷ 成本价（**原币种，不受汇率影响**）。缺成本价则不显示 |

**买卖点判定（纯阈值，机械提示，不解读）**：
- 判定统一在**人民币口径**下进行：港股当前总市值先按 HKD→CNY 折算，再与人民币阈值比较
- **理想买点命中**：当前总市值(折人民币) **<** `IdealBuyMarketCapYi` → 报告红色高亮"🔴 可以击球"
- **卖点命中**：当前总市值(折人民币) **>** `SellMarketCapYi` → 提示"可考虑卖出"
- 只要配了 `IdealBuyMarketCapYi`，观察池股票同样参与买点判定（不需要持仓）

**口径约定**：
- 单位统一用**亿元人民币**（市值类字段与买卖点阈值一律人民币；总市值原始值为元，展示换算为亿元）
- **跨市场汇率换算（v1.1 支持）**：港股金额按 **HKD→CNY** 折算。汇率**实时抓取（东财外汇 HKD/CNY）+ 失败回退 `appsettings` 静态汇率**；折算作用于市值类（当前市值/持仓市值/持股比例/组合总持仓市值）与买卖点判定。**每股价格（现价/成本价）保留原币种**（港股 HK$），报告标注币种；组合汇总处脚注注明所用汇率与时间
- 折算封装为 `Core.ICurrencyConverter`（由汇率源驱动），在编排层对港股金额统一折算后再参与聚合与判定
- 年内涨幅基准需回溯到年初首个交易日，K 线回溯天数相应加长以覆盖年初
- **证券类型（v1.1 支持 ETF）**：`StockConfig.SecurityType`（`Stock`/`Etf`；不配则按代码前缀自动识别——沪 51/56/58、深 15/16 为 ETF）。
  - **股票**：买卖点走公司总市值口径（`f116`，`IdealBuyMarketCapYi`/`SellMarketCapYi`，亿元人民币）。
  - **ETF**：`f116` 实为**基金规模(AUM)**、非估值，故买卖点改走**单位价格口径**（`IdealBuyPrice`/`SellPrice`，原币种）——现价 < 买入价→击球，现价 > 卖出价→卖点。卡片"当前市值"标签改为"基金规模"；ETF 无财报（自动空）。持仓市值/持股比例/年内涨幅/对成本盈亏与股票同口径复用。

### 5.7 报告生成

**分组显示**：报告按配置的 `Group` 分区渲染，**核心持仓在前、观察池在后**，其余分组按出现顺序排后。两类卡片信息不同：
- **核心持仓卡片**（完整）：现价 + 持仓与买卖点（5.6 全字段：持股份数/成本价/持股比例/当前市值/理想买点/1年内卖点）+ 年内涨幅 + 本周公告 + 财报/业绩 + 风险
- **观察池卡片**（精简）：现价 + 当前市值 + 理想买点 + 击球标记 + 年内涨幅 + 本周公告/风险（无持股份数/成本价/持股比例/盈亏）

**报告结构**：
- **组合概览**：核心持仓股票数、命中买点（可击球）/卖点家数、组合总持仓市值、**年度收益（年内 YTD：金额 + 收益率）**、**持仓总收益（对成本：金额 + 收益率）**
  - 年度收益（年内）：金额 = Σ(现价 − 年初收盘)×份数（折人民币），率 = 金额 ÷ 年初持仓总市值
  - 持仓总收益（对成本）：金额 = Σ(现价 − 成本价)×份数（折人民币），率 = 金额 ÷ 总成本市值；缺成本价/年初收盘的持仓分别不计入对应汇总
- **买点提示区**：命中"可以击球"的个股置顶（红色高亮），跨分组汇总
- **风险提示区**：命中风险关键词的公告/新闻集中置顶
- **分组个股卡片**：如上，核心持仓区 + 观察池区

**布局与输出格式**：
- **移动优先**：单列、卡片式布局，避免宽表格横向溢出，适配手机查看
- 输出格式（`Report.Formats` 可配）：
  - `Html`：带 `<style>` 的响应式 HTML（默认，浏览器/GitHub Pages 查看）
  - `Markdown`：默认
  - `WeChatHtml`：**公众号导出**——全内联样式（`style="..."`）、无 `<style>`/`<script>`/`<head>`，可直接粘贴进微信公众号编辑器；**预留启用**（默认不生成，`Formats` 加入即产出）
- 文件名 `reports/YYYY-MM-DD.{html|md}`（公众号导出可用 `.wechat.html` 后缀区分）

### 5.8 投递
- 默认：写入 `reports/` 目录文件，由 GitHub Actions 提交回仓库（可选开 GitHub Pages 网页查看）
- 预留：`IReportDelivery` 接口，后续接企业微信 Webhook / Server酱
- **微信公众号发布（预留）**：本期仅产出可粘贴的 `WeChatHtml` 导出，群发走**人工复制粘贴**；公众号 API 自动群发（需认证服务号 + 素材/草稿接口 + 审核）本期不做，作为后续 `IReportDelivery` 实现

### 5.9 AI 摘要（预留，默认关闭）
- `ISummarizer` 接口，默认 `NoOpSummarizer`
- 后续可接 `claude-haiku-4-5`：公告/新闻一句话摘要与利好/中性/利空风险分级

## 6. 调度（GitHub Actions cron）——周跟踪
- **每周五触发一次**（周跟踪）；cron 为 UTC 且高峰期可能延迟数分钟，需留缓冲
- 时间换算：北京时间周五 21:00（晚 9 点）= **周五 13:00 UTC**（`cron: "0 13 * * 5"`），收盘后约 5 小时，缓冲充足
- **不做交易日判断**：周五无论是否休市都照常执行；若周五为节假日，行情接口返回的是最近交易日收盘快照（原每日"交易日跳过"逻辑在周频下停用）
- 报告文件名用当周周五日期 `reports/YYYY-MM-DD.html/.md`
- 报告产物通过 `git commit` 回仓库持久化（runner 为临时环境，文件不落地）
- 采集层需重试 + 备用源 + 失败日志，应对海外 runner 访问中国行情接口的限流/失败风险

## 7. 非功能需求
- 配置与逻辑分离、无硬编码本地路径 → 便于后续迁移云端
- 网络请求含超时、重试、失败降级
- 日志记录采集与生成过程，便于调试

## 8. 已确认决策
1. ✅ 数据源：直接调用东方财富/新浪/巨潮/披露易 HTTP 接口
2. ✅ 调度（v1.1 改周跟踪）：GitHub Actions cron，**每周五 13:00 UTC（北京周五 21:00）触发一次**（`cron: "0 13 * * 5"`）；不做交易日判断，周五照常跑；公告/财报/风险内容窗口为近 7 天
3. ✅ 公告/风险：纯规则 + 关键词，重要类型过滤，AI 层预留默认关闭
4. ✅ 财报：披露提醒 + 关键财务数据 + 业绩预告/快报
